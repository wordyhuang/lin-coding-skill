# lin-coding-skill

从"一个想法"到"一套通过审查的六件套文档"的一体化 AI 编排 skill。

它以**资深需求分析师**人设与你聊透需求、主动调研方案、审计合规，最终产出符合《六件套生成 SOP》的六份标准开发文档，供林工矩阵（林枢 / LinHub 功能包）开发直接使用。

## 核心特性

- **聊透需求，不靠猜**：四阶段第一环即深度访谈——10 个维度逐项澄清（边界 / 角色 / 数据流 / 异常路径），每个需求项标 `READY` 并经你确认后才推进。
- **主动的专业建议**：用户未开口，分析师也会主动给出建议（补需求、提示风险、推荐现成方案），每条建议必须带出处。
- **三层递进调研**：① 林枢宿主服务（能不造的轮子不造）→ ② 开源社区现成方案 → ③ 大厂同类产品架构参考；每层结论三态化（✅ 复用 / ⚠️ 部分 / ❌ 自建），候选方案 ≤3 个。
- **审计前移**：方案在生成文档**之前**对照 workdesktop-ai（前端）与林枢编码规范（后端）审计，不合规回炉，避免按错误架构白写整套文档。
- **生成后审计闭环**：文档生成后再审计一次，发现问题**直接改正文**、复审至全部通过，全程不输出审计日志。
- **命名硬门禁**：产物命名严格按 SOP 规则（`{SHORT}` 短名为根）；名称不明确必须问用户，禁止占位创建。

## 四阶段流程

```
输入：用户的想法（自然语言，无 PRD 也可）
  │
  ▼
阶段1 · 需求澄清 ──→ 《需求确认单》        门禁：逐项 READY + 用户确认
  ▼
阶段2 · 三层递进调研 ──→ 《技术方案调研报告》 门禁：三态结论 + ≤3 候选 + 框架/{SHORT} 确认
  ▼
阶段3 · 规范审计（审"想法/方案"）           门禁：不合规回炉，通过才放行
  ▼
阶段4 · 六件套生成 + 生成后审计闭环          门禁：命名门禁 + A1~A6 六维审计全过
  ▼
输出：六件套 + 需求确认单 + 技术方案调研报告
```

## 安装

复制本目录到 AI 助手的用户级技能目录即可：

```
~/.workbuddy/skills/lin-coding-skill/
```

## 产物输出目录

按优先级解析，开工前向用户播报确认：

1. **agent 任务上下文（首选）**：`{任务目录}/dist/{SHORT}/`
2. 用户显式指定的目录
3. 回落默认：**询问用户确定**（禁止静默落盘）

`{SHORT}` 为用户确认的项目英文短名（如 `lin-crm`），六份文件 + `TASK-CHECKLIST.md` 均置于该目录下。

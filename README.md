# lin-coding-skill

从"一个想法"到"一套通过审查的开工包文档"的一体化 AI 编排 skill。

它以**资深需求分析师**人设与你聊透需求、主动调研方案、审计合规，最终产出符合《开工包生成 SOP》的标准开发文档，供林工矩阵（林枢 / linhub 功能包）开发直接使用。

> **什么是开工包**：一套拿到即可开工的完整交付物 = 六份标准开发文档（需求清单 / 数据库 / 后端 / 前端任务清单等）+ `TASK-CHECKLIST.md` 任务核对单 + 《需求确认单》 + 《技术方案调研报告》。

## 核心特性

- **聊透需求，不靠猜**：四阶段第一环即深度访谈——10 个维度逐项澄清（边界 / 角色 / 数据流 / 异常路径），每个需求项标 `READY` 并经你确认后才推进。
- **主动的专业建议**：用户未开口，分析师也会主动给出建议（补需求、提示风险、推荐现成方案），每条建议必须带出处。
- **三层递进调研**：① 林枢宿主服务（能不造的轮子不造）→ ② 开源社区现成方案 → ③ 大厂同类产品架构参考；每层结论三态化（✅ 复用 / ⚠️ 部分 / ❌ 自建），候选方案 ≤3 个。
- **审计前移**：方案在生成文档**之前**对照 workdesktop-ai（前端）与林枢编码规范（后端）审计，不合规回炉，避免按错误架构白写整套文档。
- **生成后审计闭环**：文档生成后再审计一次，发现问题**直接改正文**、复审至全部通过，全程不输出审计日志。
- **命名硬门禁**：产物命名严格按 SOP 规则（`{SHORT}` 短名为根）；名称不明确必须问用户，禁止占位创建。

## 四阶段流程

```
输入：用户的想法（自然语言，无 PRD 也可）
  │
  ▼
阶段1 · 需求澄清 ──→ 《需求确认单》        门禁：逐项 READY + 用户确认
  ▼
阶段2 · 三层递进调研 ──→ 《技术方案调研报告》 门禁：三态结论 + ≤3 候选 + 框架/{SHORT} 确认
  ▼
阶段3 · 规范审计（审"想法/方案"）           门禁：不合规回炉，通过才放行
  ▼
阶段4 · 开工包生成 + 生成后审计闭环          门禁：命名门禁 + A1~A6 六维审计全过
  ▼
输出：开工包 + 需求确认单 + 技术方案调研报告
```

## 产物输出目录

按优先级解析，开工前向用户播报确认：

两级结构：输出根目录由运行环境决定，输出文件夹在根目录下按短名建立。

1. **agent 任务上下文（首选）**：输出根目录 = `{任务目录}/dist/`，输出文件夹 = `{任务目录}/dist/{SHORT}/`
2. 用户显式指定的目录：输出文件夹 = `{指定目录}/{SHORT}/`
3. 回落默认：**询问用户确定**（禁止静默落盘）

`{SHORT}` 为用户确认的项目英文短名（如 `lin-crm`），六份文件 + `TASK-CHECKLIST.md` 均置于该目录下。

| 类别 | 示例说法 | 入口 |
|---|---|---|
| 想法落文档 | "我有个想法，想做个XX" / "帮我把这个点子做成林枢的开发文档" / "这个需求帮我落到可开发的文档" | 阶段 1 全流程 |
| 明确生成 | "生成开工包" / "出开工包文档" / "给这个项目生成开工包" | 阶段 1 全流程 |
| 需求梳理 | "帮我把这个需求聊透，整理成需求清单/PRD" / "我要做需求分析，最后要能生成开发文档" | 阶段 1 全流程 |
| 规范文档 | "按林枢编码规范出文档" / "按 workdesktop-ai 规范生成前端任务清单" / "出一套符合 linhub 规范的开发文档" | 阶段 1 全流程 |
| 调研触发 | "调研一下这个需求有没有现成方案/轮子" / "这个功能林枢宿主有没有现成的" | 阶段 2 起（需先补需求确认单） |
| 审计触发 | "审计一下这个方案/文档符不符合林枢规范" / "帮我检查这套文档是否合规" | 阶段 3 起（pre-gen / post-gen 模式） |

## 如何在 agent 里使用（提示词模板）

本 skill 是**一键触发 + 全程引导**式设计：你只需要给一个想法，资深需求分析师会自动完成访谈、调研、审计、生成，中途在关键节点（框架 / 短名 / 需求确认 / 命名）停下来问你。三种典型用法，直接复制粘贴即可：

### 用法 1 · 一个想法，直接落成开工包（最常见）

```
使用 lin-coding-skill。我想做一个林枢功能包：<用一两句话描述你的想法，
例如"一个客户进销存，能管客户、商品、订单和库存预警">。
帮我聊透需求，找到合适的方案，最后生成符合 linhub 规范的开工包文档。
```

### 用法 2 · 已有 PRD / 需求，直接生成文档

```
使用 lin-coding-skill。这是我现成的需求（附上 PRD 或需求文本/文件）：
<粘贴或引用>。
请按规范整理成需求确认单，调研现有方案，审计通过后直接生成开工包。
项目短名用 <SHORT>（例如 lin-crm）。
```

### 用法 3 · 只要某一段（试试看）

```
使用 lin-coding-skill，只做阶段 2：调研一下"<某个需求>"林枢宿主有没有现成能力、
开源社区有没有可复用的轮子，给 3 个候选方案和推荐理由。
```

> 提示词里可加的关键参数（可选）：`项目短名 <SHORT>`、`输出目录 <路径>`、`框架 <linshu / self_built / other>`。不加则按流程询问。
>
> **期望输出**：最终落在 `{任务目录}/dist/{SHORT}/` 下的六份标准开发文档 + `TASK-CHECKLIST.md`，外加《需求确认单》《技术方案调研报告》，拿到的就是一套可直接开工的文档。

> 仅询问林枢知识本身（如"services.php 里有哪些服务"）不触发 skill，直接回答。

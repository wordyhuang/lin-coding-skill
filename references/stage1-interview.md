# 阶段 1 · 需求澄清（访谈规程）

> 人设：**资深需求分析师**。本阶段目标：把用户的想法聊成一份边界清晰、可生成六件套的《需求确认单》。产出物 = 后续流程的"源 PRD"。

## 1. 访谈原则

1. **不靠猜**：任何模糊表述（"差不多"、"类似 XX"、"到时候再说"）一律追问澄清，禁止凭印象补全。
2. **一次问清、不连环轰炸**：每轮聚焦一个主题，问题分组给出；用户可一次回答多问。
3. **主动建议**：分析师在访谈中主动提出专业建议（用户可能没想到的：并发量、权限粒度、报表导出、异常兜底、日志审计等），每条建议注明依据；**建议只有经用户确认后才能写入需求清单**，未确认的放入"分析师建议（待确认）"区。
4. **不做技术决策**：技术框架（A/B/C）留给阶段 2 的 SOP §8 流程确认；本阶段只收集"是否并入林工矩阵 / 是否已有宿主"等事实性输入，为框架决策提供素材。

## 2. 访谈维度清单（逐维过，缺一不可）

| # | 维度 | 必须澄清到 |
|---|------|-----------|
| 1 | 业务目标 | 一句话说清"为谁解决什么问题，成功长什么样" |
| 2 | 功能范围 | 核心功能逐项列出；明确 In-Scope / Out-of-Scope |
| 3 | 用户角色 | 角色 → 权限诉求 → 使用场景 |
| 4 | 数据实体 | 主要业务对象、它们之间的关系 |
| 5 | 数据流向 | 谁录入、谁审批、谁消费；上下游系统 |
| 6 | 状态与流程 | 有审批/流转的业务必须画出状态骨架（草稿级即可） |
| 7 | 异常路径 | 撤销、驳回、并发冲突、数据缺失时的行为 |
| 8 | 边界与非功能 | 数据量级、并发、导出、权限粒度 |
| 9 | 交付形态 | 是否并入林工矩阵（决定 SOP §8 框架走向的关键事实） |
| 10 | 优先级 | M1（首期必做）/ M2（可延后）划分意向 |

## 3. 需求确认单（产出物）

按 `assets/需求确认单模板.md` 生成。规则：

- 每个需求项一行，含：编号、名称、描述、边界、角色、关联、**状态**。
- 状态机：`DRAFT`（分析师起草/待澄清）→ `READY`（描述完整且用户明确确认）。
- **用户逐项确认**：允许"批量确认"，但用户提出修改的项必须回 `DRAFT` 重新过。
- 确认单内必须含"分析师建议（待确认）"区：记录访谈中主动提出、用户尚未表态的建议。

## 4. 门禁 G1（进入阶段 2 的条件）

- [ ] 10 个访谈维度全部有明确结论（Out-of-Scope 也是结论）
- [ ] 全部需求项状态 = `READY`，且用户已确认
- [ ] "待确认"区已清空（每条建议已被采纳或明确拒绝）
- [ ] 用户确认单已按最终版定格

任一不满足 → 停在阶段 1 继续访谈，禁止推进。
